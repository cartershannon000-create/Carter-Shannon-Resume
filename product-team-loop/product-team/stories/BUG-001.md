# BUG-001 — Fix scheduleAuto closure capturing global di

**Meta:** id `BUG-001` · type `bug` · surface `live-demo` · priority score `2.3` · scope `UI-only` · files `product-team-loop/index.html`

## User value
As a visitor navigating the demo quickly, I want scene advance to stay in sync with where I navigated to, so rapid Next clicks don't cause a double-advance.

## Acceptance criteria
- [ ] `scheduleAuto` captures `di` at call time via a local `snap` variable
- [ ] The timeout callback returns early if `!playing` or `di !== snap` (navigation happened)
- [ ] No regression to normal auto-play flow
- [ ] No visual change

## Files it owns
- `product-team-loop/index.html` — `scheduleAuto` function

## Implementation
Replace the `scheduleAuto` body:
```js
function scheduleAuto(){
  clearTimeout(autoTimer);
  if(!playing) return;
  var snap = di;
  autoTimer = setTimeout(()=>{
    if(!playing || di !== snap) return;
    if(di < N-1){ dShow(di+1); scheduleAuto(); } else { playing=false; updatePlay(); updateControls(); }
  }, dScenes[snap].dur/speed);
}
```
