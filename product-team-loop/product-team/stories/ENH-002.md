# ENH-002 — Add role="tab" and aria-selected to prodbar tab buttons

**Meta:** id `ENH-002` · type `enhancement` · surface `loopband` · priority score `4.5` · scope `UI-only` · files `product-team-loop/index.html`

## User value
As a screen reader or keyboard user, I want the Overview / Live Demo tab buttons to announce themselves as tabs with a selected state, so that I understand the page structure and know which pane is active.

## Acceptance criteria
- [ ] Both tab buttons have `role="tab"` attribute
- [ ] The active tab has `aria-selected="true"`; the inactive tab has `aria-selected="false"`
- [ ] When the user switches tabs via JS (`show(name)`), the aria-selected values update to match
- [ ] The `.tabs` container already has `role="tablist"` — do not change it
- [ ] No visual change to the existing tab appearance

## Files it owns
- `product-team-loop/index.html` — add role/aria attrs to two `<button class="tab">` elements at lines 404-405; update `show()` function at line 916 to set aria-selected

## Implementation sketch
1. HTML: change the two button elements to add `role="tab"` and initial `aria-selected`:
   ```html
   <button class="tab active" data-tab="overview" role="tab" aria-selected="true">Overview</button>
   <button class="tab" data-tab="demo" role="tab" aria-selected="false">Live Demo</button>
   ```
2. In `show(name)` function, extend the tabs loop:
   `tabs.forEach(t=>{ t.classList.toggle('active', t.dataset.tab===name); t.setAttribute('aria-selected', t.dataset.tab===name ? 'true' : 'false'); });`

## Constraints
- No visual change; only attribute additions
- Keep existing `.tab.active` CSS behavior unchanged
