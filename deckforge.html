Autonomous equity-research decks

An agent that writes a deck, then critiques and rewrites it until it's boardroom-ready.

You give it a prompt. It pulls the real numbers from SEC filings, drafts a presentation, and then runs a tireless review loop — twice a day — that improves the story, the visuals, and the clarity without ever drifting from the source numbers. Every run is saved as a new version, and you get a message when it's done.

Why you can trust the output

Two kinds of work, kept strictly apart

The secret to a finance deck that won't hallucinate a number: never let the language model touch the math. DeckForge splits every job into deterministic code (the source of truth) and LLM judgment (the writing and critiquing).

Deterministic tools

Code owns every number

SEC/EDGAR fetching, parsing, analysis, the fact store, fact-checking, rendering, the scoring arithmetic, versioning, and notifications. Same input → same output, every time. If a figure isn't traceable to a filing, it can't appear in the deck.

LLM agents

Judgment owns the words

Interpreting the prompt, writing slides, reviewing for weak spots, planning a fix, and rewriting. The models arrange facts and sharpen the story — they never invent a value and never get the final say on accuracy.

Reviewer ≠ Reviser

One agent finds the weakest parts; a different agent fixes them. A critic grading its own rework drifts toward self-justification — separating them keeps the diagnosis honest.

Only accept if better

Each revision is scored against the last. It's kept only if the deck genuinely improved and no guardrail slipped — otherwise it rolls back.

A manager, not a doer

An orchestrator decides what happens next and which agent does it. It writes no code and no slides — it just routes the work and stays context-light.

The promise

It gets better at the things that matter — and never sacrifices the rest

Technical specification

0 · Orchestration model (the manager agent)

A single orchestrator coordinates everything — a manager, not a worker. The defining rule: it decides what needs to happen and which agent does it, and never does the work itself — no code, no HTML, no number-crunching, no slide-writing, no reviewing.

  • Delegates, doesn't perform. Dispatches the data tools, the Drafter, the Renderer; writes nothing into the deck or fact store.
  • Commissions reviews. It never forms its own opinion of quality — it sends the Reviewer (L4) to produce the ranked weak-parts list, then a Reviser (L6) to fix what was found.
  • Owns control flow, not content. It reads compact signals ("review returned 4 weak parts", "composite 3.83 → 3.98, accepted") and routes the next move. Every arrow in §1 is an orchestrator decision.

0a · Context discipline

The orchestrator is optimized for the smallest, highest-signal context possible — a manager buried in raw material makes worse decisions.

  • Heavy artifacts live outside its context — decks, filings, parsed tables pass between workers by reference (IDs / handles / fact_ids).
  • Workers return summaries, not dumps — counts, scores, pass/fail, a short reason, an artifact handle.
  • State lives in the persisted files (§7), not the prompt — so context doesn't grow with iteration count over a long-lived, twice-daily asset.

Two rubrics, two jobs. R1 is a one-time acceptance gate (is the first draft worth iterating on?). R2 is the per-iteration delta rubric (is this revision strictly better, and did it break an invariant?). The Score → Plan → Revise sequence mirrors a research desk: a senior reviewer marks up the deck, the work is triaged into one task, and an analyst does exactly that rework.

2 · How the rubrics are built

A rubric is only useful if its dimensions are observable, anchored, and calibrated. The Rubric Builder follows five steps and versions the result:

  • Derive dimensions from the brief (audience, thesis, sections) and domain invariants (in finance: every number sourced → hard gates).
  • Anchor each dimension with concrete descriptors at each scale point. Vague anchors are the #1 cause of judge noise.
  • Assign weights in the rubric file (not the judge prompt), so they tune without code changes.
  • Calibrate against gold examples — hand-score 3–5 reference decks; adjust anchors until the LLM judge lands within ±1 of human scores.
  • Validate & version — hold out one gold deck; require judge↔human agreement before the rubric drives the loop. Semantic-version it.
Calibration is not optional. Without it, R2's "improvement" is just judge variance and the loop climbs noise.

3 · R1 — Initial-Output Rubric (acceptance gate)

3a · Hard gates (binary — all must PASS to enter the loop)

GatePass condition
Source-of-truth100% of figures resolve to a fact-store entry with a citation. Zero unsourced numbers.
Scope coverageEvery required section from the brief is present and non-empty.
Structural validityDeck renders; no broken slides, no placeholder text, no TODOs.

Any gate fail → not "low score," but reject and rebuild (bounded by a rebuild budget, then escalate).

3b · Graded baseline (0–5 anchored; composite must clear the entry bar)

DimensionWeight"5" looks like
Thesis clarity0.30thesis up front, every section ladders to it
Coverage depth0.25drivers + risks + catalysts quantified
Narrative flow0.20story builds; each slide earns the next
Visual baseline0.15one idea per slide, charts where numbers belong

4 · R2 — Loop Improvement Rubric

4a · Protected invariants (regression = auto-reject)

InvariantMeasured byRule
Truth / source-of-truthdeterministic fact-check (not the judge)Every figure traces to the fact store. Mismatch → reject, roll back.

Story integrityjudge, coherence checkThe thesis through-line must not break.
Visual integrityjudge + render lintNo new walls of text, no overflow, no chart that carried a number removed.

4b · Improvement targets (0–5 anchored; the loop hill-climbs the composite)

DimensionWeight"5" looks like
Actionability0.25every section ends in a decision-relevant takeaway tied to the thesis
Executive altitude (C-suite fit)0.20"so what" up front; right abstraction for a CEO/CFO/board; anticipates exec questions
Visual digestibility0.20each slide graspable in <10s: one idea, right chart, clear hierarchy
Clean & concise story0.20tight through-line, no redundant slides
Metric traceability quality0.15every metric labeled inline with source, period, units
The split on numbers: the truth invariant is a binary deterministic gate ("does this number exist in the fact store?"). Traceability quality is a graded target ("is it presented so a reader can trace it?"). The first prevents fabrication; the second is a thing we improve.
R2 = 0.25·Action + 0.20·Exec + 0.20·Visual + 0.20·Story + 0.15·Trace
     (computed only when all 4a invariants hold)

5 · Accept / reject math

Let b = best-so-far, c = candidate. Accept c iff all of:

  • Invariants hold — every 4a check on c passes. One fail → reject.
  • No protected regression — for scored invariants, s_d(c) ≥ s_d(b) − τ (τ = 0 for truth/scope, 0.1 for story/visual).
  • Strict improvement — R2(c) ≥ R2(b) + δ, δ ≈ 0.15, so judge noise isn't accepted.

Otherwise roll back to b and log the attempt. Hill-climbing with rollback.

Monotonicity holds only within an epoch — by design. An epoch is a fixed (rubric_version, data_version) pair. When fresh data lands, reality can lower a score and the deck must follow — so the loop re-baselines (re-scores best-so-far against the new facts and resets the reference). Truth wins over a prettier score; score_history stamps both versions so a reality-driven drop is never mistaken for a quality regression.

Stop conditions: ship (R2(b) ≥ ship_bar ≈ 4.3) · plateau (no accepted revision for N iters) · budget (max_iters). All route to "freeze version + notify."

6a · Deterministic tools (code — the source of truth)

SkillResponsibility
T1 EDGAR/SEC fetcherPull filings (10-K/10-Q/8-K) by ticker/CIK; cache raw
T2 Document parserExtract tables & text from filings and uploads
T3 Analysis engineCompute ratios, growth, margins, bridges
T4 Fact-store writerNormalize each figure into a traceable record (value, unit, period, source)
T5 Fact-check / number-tracerConfirm every tagged figure equals its fact-store value
T6 RendererTurn the deck spec into rendered slides
T7 Render lintDetect overflow, walls of text, broken slides
T8 Score aggregatorApply weights, compute composite, run accept/reject (§5)
T9 NotifierSend email/message on run completion with status + score delta + version link
T10 Version writerFreeze the run's deck as a new immutable versions/vN/ + index row

6b · LLM agents (judgment)

SkillResponsibility
L1 Scope BuilderPrompt → frozen brief (tickers, thesis, audience, sections, tone)
L2 Rubric BuilderAuthor + calibrate R1/R2 (§2)
L3 DrafterWrite the deck from brief + fact store; tag every figure with its fact_id
L4 Reviewer / ScorerReview the deck → per-dim scores + ranked weakest-parts list + comments
L5 PlannerTriage the weak-parts list into one focused work order (target dim + action)
L6 ReviserExecute the work order — fix exactly what was flagged, nothing more
Two rules hold it together. (1) Reviewer ≠ Reviser — the agent that finds weak parts is different from the one that fixes them. (2) LLMs never own a number — every figure originates in T1–T4, is verified by T5, and is only ever arranged by an LLM.

7 · Persisted state & version history

Outputs are immutable and versioned — never overwritten. Every completed run freezes its deck as a new versions/vN/ folder; best_so_far is only a working pointer inside a run.

versions/
  v001/  deck.json  render.pdf  scores.json  changelog.jsonl   ← run 1
  v002/  deck.json  render.pdf  scores.json  changelog.jsonl   ← run 2
  v003/  ...                                                    ← newest
  index.jsonl                                                   ← one row per version
// versions/index.jsonl — one immutable row per completed run
{ "version":"v003", "ts":"2026-06-14T12:00Z", "status":"ready_for_review",
  "composite":4.12, "delta_vs_prev":+0.14, "rubric_version":"r2-1.2.0",
  "data_version":"d-2026Q1", "iters_this_run":9, "render":"versions/v003/render.pdf" }

// score_history.jsonl — one line per iteration (stamps BOTH versions)
{ "iter":8, "accepted":false, "reason":"trace 3.9→3.7 regression",
  "rubric_version":"r2-1.2.0", "data_version":"d-2026Q1" }

// notifications.jsonl — audit of every message sent
{ "version":"v003", "channel":"email", "status":"ready_for_review",
  "summary":"Run complete: composite 3.98→4.12 (+0.14), 9 iters, no invariant breaks." }

Score history separates improvement from noise; the changelog explains why the deck looks the way it does; stamping both rubric_version and data_version means a change caused by a rubric edit or by reality is never mistaken for a real improvement; the immutable versions/ stack is the progress trail the user browses.

8 · Open decisions to confirm before building

  • Thresholds — entry bar (3.2), ship bar (4.3), margin δ (0.15), plateau N, max_iters: starting guesses, calibrate on first runs.
  • Weights — R2 weights reflect "actionability + exec-fit first"; adjust to the audience.
  • Planner action taxonomy — confirm the five action types cover real reviewer comments.
  • Judge model & determinism — pin the model, low temperature, so score history is comparable.
  • Notification channel & cadence — email vs. Slack; every run vs. only on material change.
  • Run concurrency — lock so a new 2x/day trigger doesn't collide with an in-flight run.

9 · Known weaknesses (honest risks)

  • Three of four invariants rest on the LLM judge. Truth has a deterministic backstop (T5); story integrity is irreducibly the judge's opinion. Mitigated by calibration, T11, and the human gate — not guaranteed.
  • Greedy hill-climb finds local optima. "Accept only if better" blocks the transient dip a multi-slide restructure needs. Mitigation: a bounded multi-edit work order scored as one unit.
  • Cost grows with cadence. Add a compute budget per run; short-circuit a run that starts already ≥ ship bar with no new data.
  • Calibration can rot. Re-calibrate periodically; treat judge-drift flags or repeated human rejections as the signal.
  • Scope is frozen, the world is not. Only the human gate catches "the whole angle is now stale."
